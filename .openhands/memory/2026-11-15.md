## Dark-mode toggle knob bug — 2026-11-15
- User: "clicking the dark toggle does nothing when already in dark mode."
- Theme colors DO switch; what's broken is the KNOB slide. `<svg>` knob had `peer-checked:translate-x-5`, but `peer-checked` compiles to `:is(:where(.peer):checked~*)` (following sibling). The svg is inside the track span (grandchild), so it never matched.
- Diagnosed with a hand-rolled headless-Chromium CDP driver (`/usr/bin/chromium --headless=new --remote-debugging-port=...`, `websocket-client`). The browser_* tool cannot evaluate JS; CDP can, and gives ground truth (`getComputedStyle`, `getBoundingClientRect`).
- Fix in `app/components/Header.tsx`: move transform to the track span → `peer-checked:[&>svg]:translate-x-5`. Verified locally via `wrangler dev` (port 8788): knob `translate` none→20px.

## Worker CPU limit (error 1102) + bot filter — PR #192 (2026-11-16)
- Symptom: Cloudflare email "Worker reached CPU limit 100+ times in 24h" = error 1102. Free plan = 10ms CPU/request.
- ROOT CAUSE (measured with bun micro-bench): `app/routes/_renderer.tsx` `getPosts()` re-parsed ALL 83 markdown posts with `mdast-util-from-markdown` on EVERY render (~176ms CPU/req) just to build the client search index. Because `_renderer.tsx` is the global renderer, this hit every page.
- FIX: move frontmatter/HTML stripping to build time. New `app/utils/viteSearchBodies.ts` Vite plugin serves a `virtual:search-bodies` module (slug -> stripped body). `_renderer.tsx` now does `searchBodies[slug]`. Type decl in `types/virtual.d.ts` (must be an ambient .d.ts, NOT inside app/global.d.ts which is a module). Result: /blog 180ms -> 4.3ms; `fromMarkdown` gone from dist/index.js; bundle ~30KB smaller.
- Secondary heavy spots (not fixed): `/api/metadata` fetches arbitrary URLs + regex-parses HTML (SSRF/abuse risk; recommend CF rate-limit rule); `/` homepage `fetchExternalPosts` fetches+XML-parses 3 RSS feeds on cold cache (~6ms CPU, cached 10min in Cache API).
- Bot filter: `app/routes/_middleware.ts` (HonoX `_middleware.ts`, `export default createRoute(mw)`) returns 403 via `isBlockedBot` in `app/utils/botFilter.ts` (unit-tested `botFilter.test.ts`). Blocks AI/SEO/scraper UAs, allows search engines + link-preview bots. Watch out: literal substring match means 'applebot' would also match 'applebot-extended' — kept as block-only list so search bots pass. robots.txt expanded to Disallow the same AI/SEO crawlers.
- Recommend to user: enable Cloudflare Bot Fight Mode + a WAF rate-limit rule on /api/metadata (dashboard, free tier).
- Verification: typecheck/lint/build/bun test(40)/test:search/test:smoke/mcp typecheck all green. PR #192 opened, marked ready (POST .../ready_for_review 404s; use GraphQL markPullRequestReadyForReview).
